# Model Selection at a Tenth of the Cost

Answers "which AI model should we use, and did the new version get worse?" with
statistical confidence, using about a tenth of the evaluation calls a full benchmark
needs. For a team re-evaluating models every month, that is a day instead of a week and
tens of dollars instead of thousands, and it exposes the benchmark questions that were
never measuring anything.

## What this does not do

- It does not score open-ended generation. Every item is binary-scored, so the method
  measures capability, knowledge and instruction following, not writing quality.
- It assumes items are locally independent given ability. Benchmark items violate this,
  and the violation is measured and reported rather than assumed away.
- It does not write new benchmark items. It calibrates existing ones and tells you which
  of them are worth running.

## How it works

Item response theory fitted to a matrix of 100+ models by 3,000+ benchmark items built
from public per-item results, then computerised adaptive testing: pick the items that
discriminate at the model's ability level, stop when the interval is tight enough to
decide. Validated on models the calibration never saw. See [PLAN.md](PLAN.md).

## Part of a portfolio

One of fifteen projects built over twelve months. This one supplies the statistical core of

items a regression test actually needs.
